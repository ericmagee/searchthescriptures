## 1. OBJECTIVE
A seat reads and writes only the part of the engine manual its task touches. No part is larger than 40,000 characters. Nothing in the text changes at the cut.

## 2. SCOPE (one line)
Storage and access of the engine manual only: where its text is kept, how it is read and how it is written. No sentence of the manual is reworded, moved or removed by this ASK, except section 0 (how to read and revise), whose new text is in 6.4 and goes on the card.

## 4. DESIGN
4.1 New table engine_manual_parts: id, part (text, for example '09.3'), order_index (int), title (text), version (int), content (text), summary (text), created_at. One row per part per version of that part. Insert only; the same guard and audit trigger as engine_manual (no update, no delete, an audit row per insert with card and session).
4.2 One version counter for the whole manual: a write to any part takes version = (the highest version in engine_manual and engine_manual_parts) + 1. So each log row still has one version number. Versions at the cut, with N = the last whole version (241 today; 242 if the second ASK 582 pass is written first): the cut is version N+1, carried by all 31 part rows (the key of the parts table is (part, version)) AND by the pointer row in engine_manual (its own UNIQUE (version) holds, since N+1 is new there), with one log row N+1 (part NULL) that lists each part with its length and md5. The section 0 pair is version N+2, a row for part '00.1' only, with its own log row (part '00.1').
4.3 The log stays engine_manual_log, with one new nullable column part. Rows before the cut keep part NULL.
4.4 New functions:
 a. engine_manual_part_apply(p_part, p_base_version, p_base_md5, p_pairs, p_expect_md5, p_expect_len, p_title, p_summary, p_log, p_write): the logic of engine_manual_apply on one part (base = that part's latest version; each old text once; preview, then write with the expected md5 and length; it writes the log row with the part).
 b. engine_manual_part(p_part) returns the latest text of one part.
 c. engine_manual_full() returns one row (version, content): content is every part's latest text joined in order_index order with nothing between, and version is the highest part version. While the parts table is empty (before the cut) it returns the newest whole row of engine_manual instead, so a reader can move to it before the cut (W4, Wall 11211, 2a and 2c).
 d. engine_manual_toc() rewritten: one line per part (part, title, version, characters, first heading or first rule name), then how to read one part. No character offsets.
 e. Grants, as live for the objects they stand beside (3.5): engine_manual_parts has row-level security ON; SELECT to anon, authenticated, berean_ro, obsidian_ro, lab_seat; INSERT to lab_seat (not UPDATE: the guard refuses it in any case); all to postgres and service_role; policy SELECT qual true for anon and authenticated, and one for obsidian_ro (the duplicate anon policy is not copied; none for berean_ro, as live). engine_manual_part_apply: EXECUTE for postgres, service_role and lab_seat only, PUBLIC revoked. engine_manual_part, engine_manual_full and the rewritten engine_manual_toc: SECURITY INVOKER, EXECUTE for PUBLIC, anon, authenticated, service_role, lab_seat (as engine_manual_toc today), so the table's grants and policies decide what each role reads.
4.5 engine_manual keeps every row as the record. engine_manual_apply is replaced in W4's migration (6.3) so that it refuses whenever engine_manual_parts holds a row, and works as today while that table is empty; nothing is switched at the cut. It refuses with: "the engine manual is held in parts since version N; use engine_manual_part_apply". One last whole row is written whose text is only a pointer (4 lines: the manual is in parts; SELECT engine_manual_toc(); SELECT engine_manual_part('<part>'); SELECT engine_manual_full()), so that a reader that still selects the newest whole row gets the pointer and not a stale manual.
4.6 The first cut (prototype manual1123/w3/a583/split583.py, run on the v241 draft: 31 parts, largest 39,934): one part per "## " section; a section over 40,000 is cut before its top-level bullets, and a top-level bullet over 40,000 before its second-level bullets; neighbours are packed up to 40,000. Part names are section number, dot, piece number ('09.0' to '09.8', '11.0' to '11.2', '17.0', '17.1'); the text before "## 0." is '00.0' and section 0 is '00.1', so name order equals order_index (the prototype now asserts it). The cut is at entry boundaries only; no entry is split.
4.7 This first cut is by size and order, not by subject. Grouping the 141 section 9 entries by enforcer (close enforcer, gate, answer check, key word, K-UNX, anti-cheat, layers and barred moves, library and housekeeping) and moving the engine entries that now sit under section 11's snapshot bullet to their home is a second ASK: it moves text, so each move is listed, graded and shown to the operator. It is not in this build.

## 5. DEFINITION OF DONE (each can pass or fail; "found nothing" is not a pass for C1 to C3)

C1b. After the section 0 pair: md5 and length of engine_manual_full() content equal the expected values taken from the pair's preview (stated on W3's write card), and every part other than '00.1' has the md5 it had at C1.
C2. Size: no part's latest content exceeds 40,000 characters. Population: every part (31 on the draft).
C3. Write path: on a scratch copy (rolled-back transaction) engine_manual_part_apply previews and writes one pair on part '18.0'; the version is max+1; the log row carries the part; a second pair whose old text occurs twice is refused; a base md5 that is not the part's is refused; with the parts table empty engine_manual_apply previews as today; with one part row present it refuses with the pointer message.
C4. Guard: UPDATE and DELETE on engine_manual_parts are refused; an insert writes its audit row with card and session.
C5. Map: engine_manual_toc() lists every part once, in order, with its length equal to length(engine_manual_part(part)).

## 8. THIS PLAN IS WRONG IF
The parts joined do not give back the source. Checked before posting (split583.py): on the v241 draft the 31 parts joined equal the source (md5 d0e9efda3280624ce987050bc9568197, 707,670); on a known-bad copy with one character removed the join does not equal the source. Second wrong-if, not yet measured: a seat's task usually needs more than three parts at once, in which case the cut by size does not serve the objective and the grouping of 4.7 must come first. MEASURED 20:38 CST (n3_parts_per_ask.py on v241; output n3_on_v241.out): for ASK 550, 556, 549, 573, 575, 576, 581, 562, 571 and 561, each ASK is named in exactly ONE part (550, 556, 571 in '11.1'; the other seven in '11.2'). So the count passes (1, not more than 3). What it also shows: all ten sit in section 11 (Persistence), under the bullet where the batch entries were written, and none sits in section 9 with the enforcer it changes. A seat that reads part '09.x' for an enforcer will not meet these ten until 4.7 moves them. The cut by size makes each read and write small; reading by subject needs 4.7.

## 9. LIMITS

- Who uses authenticated, obsidian_ro and berean_ro is not in the record I read (3.5 d); they keep the access they have, and would read the pointer text if they select the newest whole row.
