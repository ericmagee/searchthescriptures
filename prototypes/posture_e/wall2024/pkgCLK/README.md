# pkgCLK: the closing enforcer's link is set from the closing block (W1, fault D of run 34852)
Fault (W3 grade_34852 section 3; confirmed by W4 Wall 4577): the Close Enforcer prompt says to name "the link whose closing block holds the sentence, else the link the earlier sentence supports". In 34852 the confirmed closing sentence "A man who knew himself the father would have no cause to put her away ..." stands in [CR4] under "## D2: Mary was a virgin when the conception took place". DeepSeek named LINK 3, which it copied from the candidate line (the Oracle's OPPONENT'S CONTRADICTIONS entry X2 carries "LINK 3", the link of the [CR3] drop). The engine broke D3. The judge contradiction call after the panel named LINK 2 for the same pair.
Cause: the candidate line hands DeepSeek a link number, and nothing in the code applies the first half of the rule.
Fix (Close Enforcer Record only, one node, not a library node): cecBlk finds the line of the closing round that holds the closing quotation (cecN, first part before an ellipsis, 3+ words) and reads the nearest heading above it (# to ####). When that heading begins with the side's own link token (D<n> or LINK n for the defender, C<n> or LINK n for the challenger) and names exactly one link of that side, the row's link is set to it. The row keeps link_named (the reply's link) and the note says "LINK n set by the code ... (the reply named LINK m; pkgCLK)". Otherwise the reply's link stands, as before. The declared-link check runs after the change.
