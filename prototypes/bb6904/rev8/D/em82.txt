## 1. What the engine is
The debate engine is the adversarial-testing arm of The TRUTH App: 74 active n8n workflows (91 including inactive; counted live 2026-07-25) (host `truthapp.app.n8n.cloud`) that put the Isaiah 28:10 framework in front of five AI engines (Claude, ChatGPT, Gemini, Grok, DeepSeek) in structured formats, score the results, and save every round to Supabase (project `bhffmkginddovmdcpnty`). Every debate injects the live CRITICAL/HIGH `drift_guards` and open `tensions_wall` items into the system prompt, and forces layer tags: [L1] KJV text, [L2] Hebrew/Greek, [L3] cross-reference, [L4] inference.

**THE TEMPLATE FLOW.** `3QGxwlvlgNgWPyKa` (ChatGPT Defends vs Claude) is the template for every other debate flow. A change to the pattern lands there first and is proven there; the other flows are brought to it, not fixed independently. A defect found in a sibling flow is fixed in 3QGx and ported from it. Tension to know before planning work: 3QGx carries a NO-PUBLISH bar (BB-2046), so template changes stage but do not land until the operator lifts it.

## 2. Firing a debate — quick reference
All engines are POST webhooks at `https://truthapp.app.n8n.cloud/webhook/<path>`, JSON body. Every field is defaulted — a bare `{"topic":"..."}` works for nearly all. Rows land in `debate_results` unless noted.

### The modes
- **ODV1 — Any vs Any (ORACLE_DEBATE_V1), THE CURRENT FLOW.** Any of seven engines in either seat, plain or as The Oracle (at most one Oracle), three-judge panel plus a single DeepSeek judge. Webhook `oracle-debate-v1`. See the ODV1 section at the end of this manual. The W1 and W1_CC modes below are OBSOLETE (operator, 2026-10-03) and are kept, not deleted, until ODV1 is fully verified (ODV1.0).
- **W1 — head-to-head, judged.** Claude vs one engine, 2 rounds, independent judge, HELD/BROKEN/PARTIAL verdict + diagnostic on BROKEN.
- **W1_CC — Claude challenges (seat inversion of W1).** The engine DEFENDS the standard/traditional reading; Claude goes SECOND as challenger pressing the framework's chain. Same judged shape; rows save `variant='W1_CC'`. See the dedicated W1_CC section at the end of this manual.
- **W2 — open dialog.** 2 rounds, NO verdict; exploration.
- **W3 — engine leads.** The other engine presents the standard reading first; Claude rebuts with the framework.
- **W4 — steel-man.** The other engine reconstructs the framework in its strongest form.
- **W5 — blind analysis.** Can the engine identify the method with no context.
- **W7 — adversarial.** Engine builds the strongest anti-framework case.
- **Audits** — Berean Audit (3 engines score a synthesis for bias), Tier-3 Adjudicator (Grok+ChatGPT audit a claim, Claude meta-adjudicates), Independent Synthesis (Claude-free verdict on an existing debate).

## 5. Troubleshooting — symptom → cause → fix
1. **Claude reply empty / "VALIDATION: ... empty" with stop_reason max_tokens** → thinking consumed the budget → raise max_tokens (≥16000 via model_config).
2. **Claude reply empty on a workflow with old code** → extraction reading `content[0].text` while a thinking block sits at index 0 → use `(d.content||[]).find(c=>c.type==='text')?.text` (deployed fleet-wide 2026-07-09; any NEW workflow must use it too).
3. **OpenAI 400 "max_tokens not supported"** → gpt-5.5 seat sent `max_tokens` → switch to `max_completion_tokens`.
4. **Anthropic 400 "prompt is too long: >1,000,000 tokens"** → fetch-node fan-out bomb: Fetch Drift Guards/Fetch Tensions without `executeOnce:true` multiplies items (58 guards x 35 tensions) → set `executeOnce:true` on both fetch nodes.
5. **Instant (<1s) SyntaxError on a Code node** → an editor wrote `\n` instead of `\\n` in jsCode via MCP → real newline broke a JS string → rewrite the node code with escaped newlines.
6. **"Invalid JSON in Response Body"** → Respond node has `=expr` instead of `={{ expr }}`.
7. **Not-null violation on save (e.g. null topic)** → save-body node reading `$input` when its actual upstream is a Drive node → read the named data node: `$('Format Drive Doc')...`.
8. **401 "Missing or invalid Authorization header" on Gemini** → node calling the OpenAI-compat endpoint with the native-key credential → use native `models/<model>:generateContent` + "Gemini API Key" credential (81PQ7Yd7S5c2ezLr).
9. **"Credential does not exist for type"** → Anthropic nodes must use predefinedCredentialType/anthropicApi (rGnzgJBTBRDmDPA4); Grok = httpHeaderAuth xAI (2bQmRJpPY4najNac); OpenAI (dA6k9ZaS4cl8JimR); DeepSeek (R3waesZPK7vpsV8E).
10. **42501 permission denied on a table write** → anon default-deny → route via SECURITY DEFINER RPC (e.g. log_audit_event) or add an explicit INSERT policy (audit_results got one 2026-07-09).
11. **Model "no longer available"** → provider retired it (gemini-2.0-flash-001 died 2026-07) → check provider docs, update config/node.
12. **Diagnosing a failed run when execution data is too big to read** → the Error Handler workflow (v02XXRlIhoHzMTjJ) logs lastNode+error to `debate_errors` — attach it via workflow settings errorWorkflow, re-run, read the table by SQL.

13. **Instant crash "Cannot assign to read only property 'prepareStackTrace'"** → a Code node passed a >~500-char string to execution customData.set → all topic-setting nodes now String(topic).slice(0,180) (patched fleet-wide 2026-07-10, 19 workflows); keep the pattern in new workflows.
14. **[TRUNCATED: finish_reason=length] or [stop_reason=max_tokens] inside a saved row** → the model hit its cap mid-generation; the model hit its cap mid-generation. The marker is WRITTEN (live in 24 workflows since 2026-07-10) -- but CORRECTED v16: A MARKER IS NOT A DETECTOR. Nothing ever read these markers between July and the 2026-07-25 sweep, and rows were scored over severed rounds the whole time (journal 703; todos 224/226). The execution status reads `success` either way. Until an extractor fails closed on the marker or a scheduled sweep reads it, YOU are the detector: after any model or cap change, open the SAVED ROW and search for the marker. Note the marker is written in CAPITALS -- a case-insensitive search for the word "truncated" also matches ordinary debate prose and will over-count badly (see the v16 section). Raise the seat's max_tokens in model_config.
15. **Gemini 2.5 truncates despite a raised cap** → thinking tokens count AGAINST maxOutputTokens; set maxOutputTokens = cap + thinkingBudget (the +8192 pattern, applied in G-W1).
16. **Editing a previously-edited Code node** → read the LIVE jsCode verbatim first and round-trip it byte-for-byte with replace:true; never reconstruct from a truncated view (a judge prompt was nearly lost this way 2026-07-10); nested parameters.parameters artifacts mean the visible code may not be the running code.

**The relabel.** In the v7 epoch (W1_CC rows before 2026-07-24) the judge's line-1 grade graded the CHALLENGER's chain; from 2026-07-24 it grades the DEFENDER in every variant (v10, below; EPOCH). **DEFENSE STANDING holds the defender's verdict.** Two grades, two questions: Framework Status answers "did Claude's chain survive?"; DEFENSE STANDING answers "did the defender's case stand on stated text?" A row can be HELD and COLLAPSED at once — same debate, different combatant.

**The reading protocol (required method for calling a defender HELD or not):**
1. For a W1_CC row before 2026-07-24, ignore the line-1 grade for this question — in that epoch it was the challenger's.
2. Go to the end of CR2: the UNSTATED PREMISES list names the challenged joints, numbered.

4. Apply the cite test to every CITED answer: does the verse state the claim, or something adjacent? Adjacent is not stated (canonical example in the record: Matt 1:18 "with child of the Holy Ghost" offered for the negative claim "Joseph was not the biological father" — the judge scored it a misfiled inference).
5. Check the judge's DEFENSE STANDING and CONCEDED LINKS lines against your own count.
6. Hold the asymmetry: "not refuted" is not "held." No stating verse against the defense either — the transcript answers a narrower question: what does the defense stand ON? SELF-SUPPORTED = held. PROP-DEPENDENT / COLLAPSED = did not stand on stated text.

## The Rulebook Correction (v10 — 2026-07-24)

The mangle it fixes: earlier judge prompts and transcript titles treated the framework as one of the two combatants — the DEFENDER in W1, the CHALLENGER in W1_CC — and titled the result "Framework Status." That is not the shape of a debate. **The framework is not a combatant. It is the Rules of Engagement and the Rules of Interaction — the L1-L4 layers, the burden rule, the drift guards, Isaiah 28:10 as method — and it binds BOTH fighters equally.** A debate has three seats: a DEFENDER who holds the record's reading of the TOPIC (in W1; in ORACLE_DEBATE_V1 either seat may hold the record's reading, as the Oracle, and line-1 still grades whoever sits as DEFENDER), a CHALLENGER who presses an opposing view and settles it only by breaking the defender's chain, and the JUDGE bench that rules whether the defender held. The framework is none of the three; it is the floor all three stand on.

**The line-1 verdict grades the DEFENDER, in every variant.** HELD = the defender's chain on the topic survived; PARTIAL = the defender withdrew or weakened one of his own stated claims under fire (challenger pressure alone is not a weakening); BROKEN = a core defender claim was refuted from the text. The transcript title reads **Defender's chain verdict**, because the defender is the seat being stress-tested.

**The bar cuts both ways (symmetric scoring).** The challenger no longer throws inference for free. He carries the same {STATED}/{INFERRED} burden as the defender. The defender's final LINK ROUND now closes with a CHALLENGER'S UNSTATED PREMISES list (max 6), and the challenger then faces his own LINK ROUND — cite the stating verse or concede. The judge issues two mirrored lines beneath the defender's: `CHALLENGE STANDING: SELF-SUPPORTED | PROP-DEPENDENT | COLLAPSED` and `CHALLENGER CONCEDED LINKS: <int>`, under the same mandatory-COLLAPSED floor (every listed premise conceded/unanswered => COLLAPSED). The extractor parses all four grades fail-closed (UNGRADED + loud marker on a missing line). New columns: `debate_results.challenge_standing` (text), `challenger_conceded_links` (int), `challenger_r3` (text = the challenger's link round; `engine_r3` remains the defender's link round, whichever seat the engine holds).

**Round order.** W1 (Claude defends): CR1 / DR1 / CR2 / DR2(ends with defender-props list) / CR3 defender-link-round(ends with challenger-props list) / DR3 challenger-link-round. W1_CC (engine defends): GR1 / CR1 / GR2 / CR2(ends with defender-props list) / GR3 defender-link-round(ends with challenger-props list) / CR3 challenger-link-round. The challenger's link round is a NEW node chain inserted before Build Synthesis.

**EPOCH — do not re-grade old rows.** Rows stamped before 2026-07-24 carry line-1 under the old seat rules: in W1 it graded the defender (unchanged meaning), but in W1_CC it graded Claude-the-CHALLENGER's chain. ## Layer-Admissibility (v11 — 2026-07-24)

The flaw it fixes: the LINK ROUND and the SELF-SUPPORTED definition tested support by a SINGLE VERSE — "cite the one verse that states this premise in its own words, or concede." That is proof-texting, the epistemology the framework exists to reject. A conclusion built the framework's own way — precept upon precept, line upon line, across interlocking verses (Isaiah 28:10) — has NO single verse that states it, so it was scored CONCEDED, and every defense/challenge "collapsed to conceded inference." The instrument was grading the framework by the enemy's ruler.

**The rule.** No load-bearing inference floats free of the text. Tag every claim with its layer ([L1] KJV text, [L2] Hebrew/Greek, [L3] cross-reference, [L4] inference). An [L4] counts as EVIDENCE only if it rests on and EXHIBITS the prior-layer footing it leans on — at least two of: a stating [L1] verse, an [L2] lexical ground, an [L3] cross-reference — and shows the chain from that footing to the inference. TWO EXHIBITED PRIOR LAYERS ARE THE FLOOR (ruling 2026-09-28, which REVERSES the earlier footing-sized-to-the-claim ruling recorded as ruling 2 and preserved in the v11 history above). Not all three registers are required — which two the claim leans on is the claim's own — but fewer than two exhibited layers floats free. An [L4] asserted with no exhibited prior-layer footing is INADMISSIBLE and carries zero weight. The policing is not the judge's subjective call: the ADVERSARY names any floating [L4] (that is the opponent's job), and the layer test is mechanical (footing is exhibited or it is not). The judge witnesses.

**The link round is now exhibit-or-concede.** For each listed premise: `SUPPORTED` — exhibit the [L1]/[L2]/[L3] footing and the chain to it (two exhibited prior layers is the floor; a shown chain counts equally); or `CONCEDED` — it floats free. Re-asserting without exhibiting footing is scored CONCEDED. Each side's opponent-premise list is the UNSUPPORTED-L4 PREMISES list: the load-bearing [L4]s that were not exhibited through the layers.

**Standings, redefined by footing.** SELF-SUPPORTED = every load-bearing claim is carried by its layer stack (each [L4] exhibits its [L1]/[L2]/[L3] footing). PROP-DEPENDENT = survived only because load-bearing [L4]s stood WITHOUT exhibiting footing (floating inference). COLLAPSED = rests on inadmissible claims — a majority of load-bearing links are floating [L4] conceded/unexhibited, or a claim its own texts contradict.

**COUPLING B (admissibility feeds the verdict).** The line-1 verdict is no longer independent of the standing on the failure case: if DEFENSE STANDING is COLLAPSED (a majority of load-bearing links float free), the chain has NOT held — it is PARTIAL at best, BROKEN if a core link was refuted from the text. Unsupported claims must face resistance at the top line, not only in the standing. This is why the confusing HELD+COLLAPSED pairing of the single-verse era cannot recur: an exhibited chain scores SELF-SUPPORTED and holds; a floating one is broken by the opponent and pulled down at the verdict.

**First live proof (row 4fe4caba, W1_CC defends, exec 17424):** defender DeepSeek PARTIAL / PROP-DEPENDENT / 0 conceded — it exhibited real [L1]-[L2]-[L3] footing for the covenant-joining mechanisms, but its load-bearing [L4] (the blood-specific "ethnic heathens" conclusion) floated free and collided with held record without exhibiting verses; challenger Claude SELF-SUPPORTED / 0 conceded — fully footed. The single-verse collapse is closed; the framework now judges with the framework.

### A.1.1 What a seat is

A SEAT is a named role in `model_config`, not a model name. Code MUST address seats (`M['deepseek']`), never API model strings. The seat table is the single point of substitution: swapping a provider is a `model_config` row edit, not a workflow edit.

Live seats: `deepseek`, `chatgpt`, `gemini`, `grok`, `claude_synthesis`. Every flow loads the whole roster into a map:

    const M={};$('Fetch Models').all().forEach(i=>{M[i.json.seat]=i.json;});

REQUIREMENT S-1. A flow MUST NOT hardcode an API model identifier where a seat is available. The one sanctioned exception in the live estate is `model:'claude-opus-5'` in `Build Claude R3`; it is an exception, not a pattern, and a rebuild SHOULD route it through `claude_synthesis` or a new `claude_defender` seat.

### A.1.2 The three roles in every debate

Every debate has exactly three roles and they are mutually exclusive:

1. DEFENDER — opens and holds a reading of the topic: in W1 the record's reading; in ORACLE_DEBATE_V1 the record's reading is held by whichever seat sits as the Oracle. The line-1 grade grades the DEFENDER's chain in every variant.
2. CHALLENGER — answers second, presses the opposing view.
3. INDEPENDENT JUDGE — grades. Never argues.

REQUIREMENT S-2 (THE SEAT-SEPARATION RULE, load-bearing). **The judge seat MUST NOT be either combatant's seat.** A judge that is also a combatant is grading its own argument. An unretried Fetch Drift Guards is quieter and worse than a death: the debate RUNS WITH NO GUARDS and still writes a verdict row.

*** THE TRAP THAT CAUSED NINE OF THESE GAPS — read this before cloning any node. ***
`retryOnFail`, `maxTries`, `waitBetweenTries`, `onError`, `executeOnce` and `alwaysOutputData` are NODE-LEVEL properties. They are NOT part of `parameters`. A node cloned by copying its `parameters` object faithfully — which is what this tooling invites — arrives with every one of them SILENTLY MISSING. No error, no warning, and the node looks correct in every diff of `parameters`.

### ODV1.2 Request rules (Init Seats; refusals in this order)
1. topic missing or blank.
2. a seat missing or not an object `{engine, profile}`.
3. engine not one of `claude, chatgpt, gemini, grok, mimo, glm, qwen, deepseek`. DeepSeek may now take a seat; as a debater it reads model_config seat `deepseek_debate`, not `deepseek` (the judge seat).
4. profile not `oracle` or `plain`.
5. both seats `oracle`: refused. At most one Oracle seat (BB-4671).
6. the derived panel is not exactly three seats.
Init Seats also refuses, first, ahead of item 1: a `regrade_run_token` that is not an ODV1 run token; `regrade_dry` that is not true or false, or true without a regrade token; a `rulebook` other than `current` or `draft`, or `draft` outside a dry regrade. After the panel is derived: the test inputs `test_fail_seat`, `test_fail_reserve`, `test_no_fallback` outside a dry regrade, a `test_fail_seat` not on the panel, or the other two without it; a `fence_override_id` that is not a UUID (ODV1.8, ODV1.12).
TOPIC FENCE (WALL-0788 replies 823-837): after Init Seats, Topic Fence posts the topic to `rpc/debate_topic_gate`, and Fence Check stops the run unless the gate answers `ok:true`. A fenced topic passes only with a one-use override id from `debate_fence_overrides`, created less than one hour earlier for the same topic hash; the gate marks it used with the run token. A regrade is not fenced (its stored topic is checked by Regrade Load). A gate error or no answer stops the run.
There is NO same-engine rule: one engine may hold both seats; the panel is then the first three of the other judges.
Resolve Seats refuses a seat with no ACTIVE `model_config` row, no `api_model`, or `max_tokens <= 0`. Retrieval Check stops the run before any engine call if held-record retrieval fails on a run WITH an Oracle seat; with no Oracle seat the retrieval error is recorded and the run continues.
The dashboard launcher adds its own refusals first: topic under 6 characters; engine outside the eight (deepseek included); profile; two Oracles; a fenced topic without a reason of 10 characters or more (the reason is stored in `debate_fence_overrides` and sent as a one-use `fence_override_id`). Its MiMo lock is empty: the MiMo key was verified 2026-10-09 21:07Z (audit 16842).

### ODV1.5 Rounds
D1 -> C1 -> D2 -> C2 -> D3 -> C3, each Build -> Route (by family) -> Call -> Extract.
- D1 OPENING ends with DECLARED CHAIN: 3 to 6 numbered links; the LAST is the answer to the topic (the conclusion link). Every later round is scored against this list.
- C1 CHALLENGE; D2 RESPONSE.
- C2 CLOSING ends with UNSUPPORTED-L4 PREMISES (max 6), each line starting `LINK n:` (or `LINK none:`) and carrying a verbatim quote of the defender, then `PREMISE COUNT: <n>`.
- D3 LINK ROUND: each premise answered `LINK n: SUPPORTED` (exhibiting at least two prior layers) or `LINK n: CONCEDED`; re-assertion without footing scores CONCEDED. Then CHALLENGER'S UNSUPPORTED-L4 PREMISES, same quote rule.
- C3 LINK ROUND answers that list the same way. It is structurally last; the defender's silence after it is procedural (A.2 R-4).
- Extract: empty text fails the run (`VALIDATION: ...`) through Failure Salvage, which keeps the rounds before it (ODV1.5); a provider length stop keeps the text and appends `[TRUNCATED: the provider reported the token limit -- raise max_tokens]`. Since ORDER J (BB-6200; published a39cc3eb) the empty-text message names what the provider reported: `returned no text: finish_reason=<x>; output_tokens=<n>; reasoning_tokens=<n>; reasoning_chars=<n>`, plus `; error=<first 200 characters>` when the reply carries a provider error; Failure Salvage carries it into debate_errors. The text path is unchanged (96 of 96 test outputs byte-identical, BB-6205). Not yet exercised live: no round has come back empty since (BB-6210).
- Retry (A.2 R-7): openai debate calls 4 tries, grok 2, other debate families 3, wait 5000; every debate and judge call has a 900 s timeout; Fetch nodes 3 x 3000; Save to DB 4; Retrieve Held Conclusions 3 x 5000 with continueRegularOutput; Write Judgment 1-3 and Derive Outcome 3 x 3000 (ORDER D, BB-6036; both functions idempotent). The error outputs of every round call, the synthesis, single-judge and diagnostic calls and Save to DB, and of the checks that throw on a bad reply (the six round Extracts, the three Normalizers, Final Output, Extract Diagnostic, Check Save), go to Failure Salvage (ORDER D, published e2c17dd8): it saves the rounds produced as a contested row (framework_verdict null; quarantine_reason and a REVIEW THIS ROW line naming the node) and a RUN INCOMPLETE file in the Drive study folder, the file alone when the save itself failed; Salvage Stop then throws with the row and file outcome, so the run still fails and the Error Handler still files debate_errors. In test mode the token begins ODV1-TEST- and the file name "TEST - ". Tested with pinned data on each class (BB-6063); deployed and UNEXERCISED in production (BB-6077). Only the Fetch nodes' error outputs still route to Stop: Call Failed, which throws `ORACLE_DEBATE_V1: call failed at node "<node>": <message> run_token=<token>`. The panel stage's error outputs (Panel Build, Panel Check, Reserve Build, Record Substitution, Panel Payloads, Write Judgment 1-3, Derive Outcome, Panel Done, Write Replay) go to Panel Failure Note (ODV1.8); Topic Fence's goes to Fence Check (ODV1.2).
- PROVIDER REFUSAL (BB-6755 G1): every round extract treats a provider refusal as a failed call, not a round: OpenAI-compatible finish_reason content_filter or a non-empty message.refusal; on OpenRouter also native_finish_reason content_filter, refusal or one of the Gemini reasons below; Anthropic stop_reason refusal; Gemini finishReason SAFETY, RECITATION, BLOCKLIST, PROHIBITED_CONTENT, SPII, IMAGE_SAFETY, IMAGE_PROHIBITED_CONTENT, or any promptFeedback.blockReason. Gemini finishReason OTHER and LANGUAGE stay ordinary (BB-6763). The extract throws "refused by the provider", naming round, side, family, model and reason, and the run takes the failed-call path: Failure Salvage saves a contested row ("no verdict stands on this row") and a RUN INCOMPLETE file, then Salvage Stop fails the run; no panel, no outcome. Before this (ODV1-27177) a refusal was saved and judged as a forfeit.

### ODV1.6 Synthesis, single judge, diagnostic (the single judge: the first engine in the judge order not seated)
- WHO: Init Seats sets `single_judge` = the first of `deepseek, gemini, grok, chatgpt, mimo, glm, qwen` not seated; it writes the synthesis, gives the single verdict and writes the diagnostic. - Synthesis: cap max(max_tokens, 20000); asks what held, both link rounds' results, drift-guard violations, how each side engaged; no verdict. - SINGLE JUDGE (Build Independent Verdict, prompt id ODV1-A1): cap max(max_tokens, 8000); DeepSeek as single judge at least 65,536 (BB-5735 step 3: at 32,000 its answer was cut off). The single judge and the panel are given the citation report ("CITATION CHECK AGAINST THE KJV", ODV1.13). The full rulebook: layer rules, framework-not-combatant, chain scope, COUNTING RULE (count only from the two link rounds; the synthesis is context only), VERDICT DEFINITIONS applied mechanically, first match wins:
  - BROKEN-1: k >= 1, a declared defender link refuted from the text at a collision.
  - BROKEN-2: 2w > n, or the keystone (the last declared link, the conclusion) is WITHDRAWN.
  - PARTIAL-1: w >= 1.
  - PARTIAL-2: DEFENSE STANDING is COLLAPSED.
  - HELD-1: none of the above.
  (n = declared links; w = links the defender's own link round withdraws; k = links graded DEFENDER LINK BROKEN.)
  Standings for each side: SELF-SUPPORTED = every listed claim shows its footing (at least two prior layers); PROP-DEPENDENT = the side stood only because listed [L4]s were allowed to stand without exhibited footing (links conceded or unexhibited in its link round) -- this is a DEMOTION, not a pass; COLLAPSED = by count only, 2c > L, where L counts ONLY the premises the OTHER side listed AGAINST this side (the challenger's list closing round 2 for the defender; the defender's list closing its link round for the challenger) and c the ones this side conceded or left unexhibited; a tie is NOT COLLAPSED. Each standing line carries its counts after the grade, "-- L=<L> c=<c> --" (W1; BB-5895, BB-5988). A side's OWN outgoing list never enters its own L or c. FORFEIT (operator-approved 2026-10-04): if the other side listed no premises against a side (empty list, or PREMISE COUNT: 0), that side's L = 0, c = 0, it cannot be COLLAPSED, and the judge writes LINK ROUND FORFEITED: CHALLENGER (or DEFENDER). The same text is in the panel prompt. Why: on ODV1-23985 the challenger listed nothing; all four judges counted the defender's six outgoing premises as its concessions and graded the defense COLLAPSED and the verdict PARTIAL. ### ODV1.7 Persistence (crossed columns -- read this before any query)
Saved via `rpc/record_debate_row` (A.6) BEFORE the panel runs. The save is idempotent on `run_token` (partial unique index `debate_results_run_token_uniq`; a repeat call returns the existing row with `existing` true and inserts nothing), so Save to DB's retry cannot write a second row (ORDER D, BB-6055). ### ODV1.12 Panel regrade (added v58, 2026-10-09, operator ruling)
- PURPOSE: a run whose debate was saved but whose panel stage failed (an INCOMPLETE run) is re-judged in the ONE flow, not in a new workflow. The rounds, the synthesis, the single judge and the save are NOT re-run.

Init Seats keeps that token (it does not mint a new one) and sets `regrade: true`.
- PATH: Respond Accepted -> Regrade? (true) -> Regrade Row (reads `debate_results` by run token) -> Regrade Judgments (reads `debate_judgments` for the debate) -> Regrade Served Conclusions -> Regrade Served Sights (read `kb_conclusions` and `kb_sights` for the row's served labels) -> Regrade Load -> Citation Scan -> Cited Verses -> Quote Compare -> Find Words -> Quote Report -> Regrade After Quotes? It writes NO judgment, NO outcome and NO document; a failed dry regrade ends at Dry Failure Stop. It may re-judge a run that already has judgments. ### ODV1.13 Citation check against the KJV (added v62)
- PATH: on a normal run, Final Output -> Citation Scan -> Cited Verses -> Quote Compare -> Find Words -> Quote Report -> Regrade After Quotes? (false) -> Build Independent Verdict; on a regrade, Regrade Load -> the same five -> Regrade After Quotes? (true) -> Panel Build. The report goes to the single judge and the panel ("CITATION CHECK AGAINST THE KJV") and to the document.
- Citation Scan pairs every quotation with its verse reference in the six rounds: reference then quote, quote then reference (in parentheses, after a dash, or a line-opening quote followed by a layer tag and its reference), short book names; a line opening with [L2] is skipped (a gloss of the Greek or Hebrew); a reference inside a quotation is skipped; a nearer reference standing between the reference and the quote, or bracketed after the quote, is tried when the first reference fails (operator ruling 4, 2026-10-13).
- Quote Report gives each quotation MATCHES, WORDS ARE AT <ref>, WORDING NOT FOUND IN <book>, CITED VERSE DOES NOT EXIST, or NOT CHECKED (too short). A non-matching quote is reported only when offered as the verse (citation form, BB-5773); a quote with an Arabic numeral, or a reference the speaker attributes to the opponent, is a phrase. So is a quote whose words the OTHER side wrote, outside quotation marks, in a round filed earlier (round order D1 C1 D2 C2 D3 C3; BB-5892): it is the opponent's sentence, not the verse (offline replay of 34 rows; not yet shown live). A failed read gives "not available this run".

- KNOWN LIMIT of that rule: it marks a quote a phrase whenever the opponent wrote the same words earlier outside quotation marks, matching or not. On the 34 rows it changed 31 items: 4 were the false reports above, and the other 27 (12 matching, 15 too short to check) are never reported either way; a future real misquote in words the opponent had already written would go unreported.
