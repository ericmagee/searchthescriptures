TITLE: A manual run of an n8n workflow executes the saved draft, not the published version: replay a draft before publish, and prove the route by a mark only the draft can write
TRIGGER: You are about to test a change to an n8n workflow before publishing it, or you are reading a run as evidence about code that is saved but not yet published.
BODY: In n8n the webhook (production) trigger runs the ACTIVE (published) version; execute_workflow with executionMode manual runs the SAVED DRAFT. So a saved, unpublished change can be exercised on stored input before the publish, which a webhook run cannot do. THE ROUTE IS A CLAIM UNTIL PROVEN: fire one canary first and pass it only if its output carries a mark that only the draft's code can write (a new audit string, a new count); a run that shows no such mark proves nothing about the draft, and the route is then UNEXERCISED. THE MANUAL RUN STILL MAKES EVERY WRITE ITS PATH MAKES: use a dry path (here regrade_dry, writing only debate_replay_judgments) and read the baselines of every table the live path writes before and after. After the publish, the live run (webhook or production mode) is still owed: the replay tests the draft on old input, not the published flow.
MOTIVATING FAILURE: Order BB-7994 step 6b: twenty nodes were written to the draft and verified by fetch-back (BB-8151, 8152), but the plan could not say how a replay would reach unpublished code, since the webhook runs the active version (BB-8152 open point). A replay through the webhook would have graded the old code and passed or failed nothing about the change.
